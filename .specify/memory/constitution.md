# Full-Stack Todo Web Application Constitution

## Core Principles

### Spec-Driven Development (NON-NEGOTIABLE)
All implementation must follow spec-driven development using Spec-Kit Plus and Claude Code; Zero manual coding allowed - all changes must be generated via Claude Code prompts referencing @specs/ files; Every feature must be planned and documented before implementation.

### Security First Architecture
Authentication MUST use Better Auth (frontend) + JWT plugin + FastAPI backend verification; All API endpoints must enforce user ownership (filter by authenticated user.id); No data leakage between users allowed; Proper JWT verification required on all protected endpoints.

### Monorepo Structure Compliance
Strict adherence to monorepo structure: frontend/, backend/, specs/, .spec-kit/config.yaml; Every code change must reference at least one @specs/... file; Layered CLAUDE.md guidelines must be followed at root, frontend, and backend levels.

### Tech Stack Adherence
Use only allowed tech stack: Next.js 16+ App Router, FastAPI, SQLModel, Neon PostgreSQL, Better Auth + JWT; No additional libraries unless explicitly mentioned in specs or hackathon rules; Database schema must match exactly /specs/database/schema.md (users + tasks table).

### End-to-End Feature Completeness
All 5 basic task features (Task CRUD + toggle complete) must work end-to-end with authentication; Every API request requires valid JWT → 401 if missing/invalid; Responsive frontend with Tailwind CSS, using server components by default.

### Zero Manual Coding Enforcement
No manual coding allowed - all implementation via Claude Code prompts referencing @specs/ files; Plagiarism check: 100% original code generated by Claude Code based on specs; Every change traceable to specific spec files and CLAUDE.md guidelines.

## Additional Constraints

Technology stack requirements: Next.js 16+ App Router, FastAPI, SQLModel, Neon PostgreSQL, Better Auth + JWT; JWT secret: Use same BETTER_AUTH_SECRET env var in both frontend (Better Auth) and backend (verification); Token verification in FastAPI: Use jose / PyJWT library to verify against JWKS or shared secret; No hard-coded secrets, use environment variables only.

Database schema must match exactly /specs/database/schema.md (users + tasks table); Error handling: proper HTTPException in backend, user-friendly messages in frontend; Code style: follow patterns in /frontend/CLAUDE.md and /backend/CLAUDE.md strictly.

## Development Workflow

Development workflow: Write/Update spec → Reference in prompt → Let Claude Code implement → Test & iterate; Success criteria: All 5 basic task features working end-to-end with authentication, every API request requires valid JWT, users can only see/modify their own tasks, database persistence via Neon PostgreSQL with SQLModel models, JWT flow working: Login → Get JWT → Attach to API calls → Backend verifies & filters.

Every code change must reference at least one @specs/... file; Complete accuracy with hackathon requirements and provided technology stack; Maximum reproducibility: every change traceable to specific spec files and CLAUDE.md guidelines.

## Governance

Constitution supersedes all other practices; Amendments require documentation, approval, migration plan; All PRs/reviews must verify compliance with spec-driven development, security requirements, and tech stack adherence; Changes must be justified with reference to @specs/ files; Use CLAUDE.md for runtime development guidance.
